# 环境检查与自动配置

普通用户在 Windows x64 上双击根目录 `start.cmd`。不要求预先安装 Python、Node、Ollama、CUDA Toolkit、Docker 或 WSL。首次启动需要联网和项目目录写入权限，程序按需准备运行环境；模型权重仍由用户选择接入方式后下载。

## 首次启动

1. 检查 Windows x64 和 Microsoft Visual C++ 运行库。缺少运行库时下载微软官方安装器，验证 Microsoft Authenticode 签名，再调用安装；系统可能弹出管理员授权。不自动重启电脑。
2. 检查项目 `.venv` 中的 Python 3.12。缺失/损坏时下载并校验固定版本 uv，由 uv 安装项目专用 Python 并创建虚拟环境。旧环境保留为备份，不删除；不修改系统 PATH 或 Python 注册表。
3. 检查 `requirements.lock` 的实际版本、平台条件和依赖一致性，缺失时自动安装，再验证应用模块可导入。
4. 检查前端构建产物与源码指纹。页面缺失或源码更新时，自动使用可用 Node 22+ / npm；没有完整工具链时下载校验项目专用 Node，再安装锁定依赖并构建。
5. 仅在 `.env` 不存在时生成默认 SQLite / 本地任务队列配置与随机运行时令牌。已有数据库、API、模型配置不覆盖。

应用启动前验证数据库和队列。已有、本项目登记的本机 PostgreSQL/Redis 不可用时尝试恢复；外部服务不自动重配，也不静默改用另一数据库。首次安装默认本机 SQLite，无需用户安装基础服务。`--lightweight` 明确使用另一个 SQLite 工作空间，不搬迁旧聊天数据。

下载显示真实字节或阶段，包安装/构建显示执行阶段与日志，不按时间伪造百分比。网络失败后重新启动可复用已校验的下载和包缓存。uv、Node、Python、模型、日志与缓存位于项目 `data/` 下；首次引导只需 Windows 自带 PowerShell。

## 模型设置中的环境检查

侧栏「模型」→「环境检查」显示应用、页面、数据库/队列、磁盘、系统内存、NVIDIA 驱动、本地运行时和研究组合依赖。

- **配置本地模型环境**：下载或复用独立 Ollama，启动本机服务并验证；不下载模型权重。
- **配置组合推理环境**：先检查硬件，再复用已验证环境，或自动创建隔离的 PyTorch CUDA / Diffusers 等环境并验证。无需单独安装完整 CUDA Toolkit。
- 配置任务在独立进程中运行，和模型下载共享安装锁，防止并发修改环境。支持查看逐项状态、后台继续、取消和失败后重试。
- 直接点击某种模型的「下载并部署」也会自动检查硬件和补齐环境，不要求先进入此页操作。

当前固定研究组合需要 NVIDIA GPU。没有显卡、驱动过旧、磁盘不足或 Windows 要求管理员权限/重启时，显示具体原因；不把硬件问题伪装成已修复。无 NVIDIA GPU 时仍可配置 API 或尝试 Ollama CPU 主控，但不能声称研究图像组合可用。

## 诊断与恢复

```powershell
.\start.cmd --setup-only  # 检查/安装应用环境，不启动服务
.\start.cmd --repair      # 重新安装锁定应用依赖并检查页面，然后启动
.\start.cmd --lightweight # 明确使用独立本机数据库
```

应用阶段记录：`data/environment/bootstrap.json`；环境任务记录：`data/environment/repair.json`；日志：`data/logs/bootstrap.log`、`deployments.log`、`services.log`。环境检查响应不输出 API Key 或数据库密码。

当前自动首次安装面向 Windows x64。源码开发者仍可手动安装；完整免安装桌面发行包、其他系统首次引导、显卡驱动升级及系统重启自动化不作为已交付能力。

## 实现依据与验证

- [uv Python 管理](https://docs.astral.sh/uv/guides/install-python/)及[环境变量](https://docs.astral.sh/uv/reference/environment/)：项目专用 Python、缓存目录及禁止注册表/PATH 安装。
- [uv 0.13.5 发布](https://github.com/astral-sh/uv/releases/tag/0.13.5)：固定 Windows x64 包及 SHA256。
- [Node 22 官方校验清单](https://nodejs.org/dist/v22.23.4/SHASUMS256.txt)：固定 Windows x64 ZIP 校验。
- [微软 VC++ 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/)与 [CUDA 12.4 驱动兼容说明](https://docs.nvidia.com/cuda/archive/12.4.0/cuda-toolkit-release-notes/index.html)：系统依赖及驱动检查。

自动化测试覆盖平台条件依赖、配置保留、前端产物/源码变更、前端安装目录、硬件阻塞、配置任务持久化/取消/互斥、响应脱敏及外部数据库不被替换。`scripts/verify_fresh_setup.py` 在项目内隔离目录排除系统 Python/Node 路径，实际安装专用运行时与应用依赖、构建页面，并启动独立端口验证空模型工作台；这不等同于重装 Windows 或完整研究组合的全量权重验收。
