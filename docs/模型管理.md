# 模型管理与自动部署

更新：2026-10-24。本轮实现取代顶部的固定三模式下拉框。用户先添加具体模型连接，再在角色输入框下方选择；同一方式可以拥有多个 API 连接或不同的本地模型。

## 使用方式

侧栏底部「模型」打开居中管理弹窗。列表显示连接名称、来源和状态，支持选用、编辑 API、删除连接。新增入口分为：

| 方式 | 用户填写 / 查看 | 后台处理 |
|---|---|---|
| API 添加 | 名称、Base URL、模型 ID、Key，可单独填写视觉模型 ID | 保存独立连接；调用兼容 Chat Completions 接口。保存配置不代表第三方 API 已实测连通 |
| 本地部署 | 选择 Qwen3 通用指令、Qwen3-VL，或输入 Ollama 本地标签 | 流式下载并校验，检查 completion/vision 能力并实际加载。视觉模型验证图片输入；纯文字模型使用已有本地 Qwen3-VL 处理图片，并在列表注明分工 |
| 多模型组合 | 查看固定清单，无组件选择 | 准备隔离推理环境，按顺序准备 Qwen3-VL、Illustrious XL、VAE、ControlNet、SAM2、BGE-M3、Reranker、Anime LaMa、SDXL 配置/分词器；复用完整已有文件，启动并验证主控 |

本地自动运行时安装支持 Windows x64；其他系统须先安装 Ollama。研究组合需要 NVIDIA CUDA，环境安装使用固定的 PyTorch CUDA 12.4 和依赖版本。Windows 首次启动也会自动准备应用自身的 Python/Node 与依赖，详见 [环境自动配置](环境自动配置.md)。尚未交付免安装桌面发行包。

Qwen3-VL/当前 API 提供理解、规划和回答，图像迁移与修复使用本地组合工具。只添加 API 或 Ollama 主控不会自动获得图像执行权重。角色专属 LoRA 随角色包导入；基础模型下载不生成角色权重。PPO 策略仍未接入，当前修复使用 LaMa。

2026-10-25：支持以纯文字模型担任主控。部署器对通用模型验证 completion 能力与真实文字生成；只有已存在本地 Qwen3-VL 权重才发布为就绪。任务快照独立冻结 controller_source 和 vision_source，文字与图片分别路由。Ollama 显式关闭 thinking，避免短输出预算被思考占满；每次调用后卸载模型，兼容本机 8GB 显存的顺序调用，代价是额外加载时间。自建评测与选型结果见 [Agent质量与改进验收](Agent质量与改进验收.md)。

## 进度、取消与恢复

部署由独立 Python 进程执行，记录保存在 `data/deployments/<模型ID>.json`。关闭弹窗不终止部署；重新打开可查看原任务。每项依次显示等待、运行、完成或失败，下载显示真实字节；多文件模型合计该组件的文件大小。运行时安装、环境安装和加载验证显示阶段状态，不能按时间伪造百分比。

全局部署锁使多个部署任务顺序执行。取消标记保存在磁盘，下载/安装轮询后停止；重试保留已验证的权重和断点缓存。HTTP 文件下载将 revision/URL/哈希与断点关联，避免跨版本误续传。Ollama 下载由其内容寻址缓存恢复。进程意外退出后显示中断并允许重试，不假装继续运行。

研究组合的推理源码快照位于 `vendor/endless`，包含来源哈希，不含权重、训练入口或私密配置。在没有完整研究安装的机器上复制到 `data/bundle/endless`；安装器不向同级研究仓库下载或改写文件。

## 配置与运行

- `data/model-registry.json`：公开连接元数据与默认选择。
- `data/model-secrets.json`：独立 Key；响应、日志和任务快照不包含 Key。文件按当前用户权限保存，未声称硬件加密存储。
- `data/runtimes/ollama`：官方独立运行时，固定版本及 SHA256。
- `data/models/ollama`：托管 Ollama 权重。服务只绑定 `127.0.0.1:11435`，不接管系统默认端口。
- `data/runtimes/torch`：需要时创建的隔离研究推理环境。
- `data/logs/deployments.log`、`ollama.log`：部署和运行日志。

删除操作移除连接和 Key，保留共享权重/运行时，避免删除另一个连接正在复用的文件；有在途任务或正在部署时拒绝删除。任务保存实际 URL、模型 ID、连接 ID、网络策略快照，切换/编辑只影响后续任务。API Key 按连接和密钥版本引用读取，避免编辑 URL/Key 后旧任务把新密钥发送到旧地址。

主页三张功能卡只展示，无配置或点击入口。迁移、角色知识、修复和一致性检查均从角色窗口使用；后端拒绝新建未绑定角色的会话以及向历史通用会话发送任务。

官方依据：[Ollama Windows](https://docs.ollama.com/windows)、[官方固定运行时发布](https://github.com/ollama/ollama/releases/tag/v0.40.10)、[Qwen3-VL Ollama 模型库](https://ollama.com/library/qwen3-vl)、[LaMa 权重](https://huggingface.co/df1412/anime-big-lama)。

## 验证边界

自动测试覆盖独立 API 配置、密钥不回显、任务快照、角色范围、断点下载、哈希失败不发布文件、取消、ZIP 路径保护与不完整权重识别。浏览器测试覆盖桌面、手机、API 增删改/持久化、固定清单以及关闭重开后的下载进度。

本机已实测组合安装复用现有环境/权重并自动补齐 SDXL 配置。完整的空白机器研究环境与数十 GB 全量重新下载尚未跑完独立验收；已有环境复用成功不能代替这项验证。第三方 API 无真实 Key，不声称外部调用验收通过。自动部署通过也不改变既有迁移模型效果尚未达标的结论。

本地部署已实际下载官方 Ollama 运行时和 Qwen3-VL 2B Instruct（约 1.93 GB 模型文件），完成加载与真实图片输入验证；同一角色会话中切换本地 2B 和研究组合主控均执行成功。规划输出通过工具白名单和结构校验，格式失败最多重试一次；仍失败则解释原因，不执行猜测的工具。默认模型使用显式 `-instruct` 标签。

本机 WSL 服务当前被禁用，运行中的预览使用 `start.cmd --lightweight` 和独立 SQLite 数据库，不改写原 PostgreSQL 配置/数据。新机器默认本机配置，可先打开模型管理，再准备模型；应用自身依赖由启动器检查并自动配置。
