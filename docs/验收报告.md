# Endlexx 首版验收

2026-10-25 的模型对照、摘要改进和重新验收见 [Agent质量与改进验收](Agent质量与改进验收.md)。本文保留首版的历史测量，不将不同版本、样例和时刻的结果混写。

日期：2026-10-24。环境：Windows、RTX 4060 Laptop 8GB；API 与 Worker 为本机独立 Python 环境，PostgreSQL 16 / pgvector 和 Redis 位于 WSL。应用依赖锁定于 `requirements.lock`，前端依赖锁定于 `frontend/package-lock.json`。

动漫修复样例使用 512×768 角色图片，额外人为加入白色遮挡；请求仅为“修复这张图片中的局部缺损，保持其他区域不变。”，未提供坐标或蒙版。实际执行约 41.3 秒，内部蒙版占约 1.61%，保护区变化为 0 像素。该样例只验证此类局部擦除的定位与补全流程，不代表任意破损均能自动识别。

一致性检查使用单独的“验收样例（非正式角色）”，没有把自动生成的正式角色描述擅自确认为标准。当前 4B 本地模型在这一样例中的结果如下：

| 项目 | 人工验收标注 | 实际报告 |
|---|---|---|
| 深棕色长发 | match | match |
| 白色吊带服装 | match | match |
| 设定要求黑框眼镜，图中未佩戴 | mismatch | unknown，复核后仍未正确识别缺失 |
| 脚在画外，无法检查鞋子 | not_visible | not_visible |

因此 `scripts/smoke_agent.py check` 当前会非零退出，保留这条失败的视觉质量断言。程序状态 completed 表示报告已生成，不能当作质量验收通过。应用保留原始观察和复核记录，待定结果需要人工核对；后续应更换/增强视觉模型并扩大独立验收集，而不是修改断言或把 uncertain 强行转成 mismatch。

## 检索消融

语料和标注见 `evals/rag_fixture.json`：12 份短篇虚构设定、12 个问题，覆盖不同设定版本、台词、外观、服装和语义改写。各方法共用相同角色与版本过滤。运行前预热模型，时延是单请求本机测量值，不代表并发性能。

| 方法 | Recall@3 | MRR@3 | P50 | 样本 P95 |
|---|---:|---:|---:|---:|
| BM25 | 1.000 | 0.958 | 0.006 秒 | 0.012 秒 |
| BGE-M3 向量 | 1.000 | 1.000 | 1.341 秒 | 1.373 秒 |
| BM25 + 向量 + RRF | 1.000 | 0.958 | 1.341 秒 | 1.353 秒 |
| 混合 + BGE Reranker | 1.000 | 1.000 | 3.389 秒 | 3.608 秒 |

这组数据只证明实际查询、版本过滤和消融流程运行正常，样本规模不足以支持泛化结论。当前重排增加 CPU 时延，默认完整链路便于继续比较；真实规模扩大后应据数据决定是否启用。尚未在独立真实语料上测量无依据拒答、引用正确率或大规模吞吐量。

## 图像运行策略

首轮迁移使用研究入口原配置。应用另提供 `balanced` 策略：通过本项目启动适配器调用同一 `Endless/test.py`，在进程内应用 SDPA 和按组件 CPU 卸载，保留权重、分辨率、步数和业务逻辑。`research` 策略可用于对照，不修改同级项目源码。

同一人物输入、同一 `ayaka` 发布包、相同 28 步配置，在本机各执行一次。下面是 Endless 入口日志的耗时，排除排队和 Agent 文字问答；单样本不能代表所有图片的速度。

| 运行策略 | 主体生成 | 头部强化 | 入口总耗时 |
|---|---:|---:|---:|
| research | 335.5 秒 | 471.3 秒 | 1335 秒 |
| balanced | 230.8 秒 | 267.8 秒 | 793 秒 |

此样例入口总耗时减少约 40.6%，仍不适合即时交互，因此使用后台任务与进度心跳。两次输出均已人工查看：存在明显色阶断裂、局部块状伪影，角色外观迁移也不充分。**本轮仅通过接入和执行验收，没有通过角色迁移的视觉质量验收。** 后续需要在 Endless 侧排查角色包、生成与区域合成效果；不将运行加速表述成画质提升。

资源策略参考 [Diffusers Pipeline 官方文档](https://huggingface.co/docs/diffusers/api/pipelines/overview)。具体速度和效果以本机验收为准，不把机制描述当作测量结果。

修复当前仅覆盖可可靠定位的局部浅色/深色色块缺损，不代表通用自动破损检测。旧 PPO 缺少原始 StateEncoder，未启用，不将 LaMa 结果标为 PPO 增强。

机器可读原始报告与截图保存在被 Git 忽略的 `data/verification/`。开发联调曾出现的失败不能当作成功验收，报告以最终对应任务状态和真实产物为准。
